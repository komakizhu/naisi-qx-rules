# QX 实机验收清单（尚未执行）

此处是可重复的手机检查步骤，不是已经通过的测试结果。先保持 Cats-Team、Google 重定向和全部节点/策略/DNS/证书不变，只增加奶思重写资源，记录 QX 版本与 build、iOS 版本和各 App 版本。

## 资源与 MITM

1. 确认 QX 是 1.5.2 或以上；导入后查看有无解析错误，核对有效重写数量与 validation-report.md。
2. 保持已有 MITM 证书，确认系统已经信任；不重置证书，不替换 passphrase 或 p12。
3. 启用重写与 MITM，查看资源 hostname 是否加载。不要把原版全部 hostname 或 `*` 手动覆盖到主配置。
4. 按 README 将配套 JSON 放入本机 QX/Data，检查彩云相应接口的返回正文。
5. 遇到 SSL/连接失败，先只关闭该奶思资源复测。hostname-audit.json 标为 optional/unresolved 的项先不加宽范围；上游“无法 MITM”的结论并未经本项目实测。

## 记录与定位

记录具体失败动作、时间、资源开关、QX 的解析/脚本错误、命中的规则/URL 及对应原行。请去除 token、Cookie、手机号和个人订单信息后再反馈。一次只停用可疑规则或资源，避免用“关闭所有去广告”掩盖问题。

只有 URL 真正命中、脚本成功返回、广告消失且正常功能回归后，才把该项标为实机通过。重写静态存在、HTTP 200 或屏幕暂时没有广告都不能单独证明成功。

## 自动更新回归

转换器日志和 manifest.json 中应能追溯新官方 commit；QX 刷新到新文件后再次核对资源内容/规则数、脚本加载与 hostname。彩云本地 Data 不会被远程订阅自动同步，需复制新文件。出现问题时仅回退奶思资源文件，不恢复/覆盖整份个人主配置。
